# Напоминалка для Windows 10

Приложение-напоминалка на Python: хранит напоминания в базе данных **SQLite3**,
показывает их в интерфейсе на **tkinter** и уведомляет о срабатывании —
системным уведомлением Windows 10 или всплывающим окном поверх всех окон.

Уведомления работают даже когда окно программы свёрнуто.

---

## Возможности

- Добавление нового напоминания (заголовок, описание, дата и время срабатывания).
- Повторяющиеся напоминания: ежедневно, еженедельно, ежемесячно, с датой окончания.
- Удаление напоминания (с подтверждением).
- Отметка напоминания как **«Готово»** или **«Отменено»**, а также возврат в **«Ожидает»**.
- Автоматический перевод просроченных напоминаний в статус **«Просрочено»**.
- Просмотр всех напоминаний с фильтром по статусу.
- Хранение в SQLite3; при старте приложение проверяет и создаёт таблицы, если их нет.
- Уведомление о срабатывании: системное уведомление Windows 10
  (через `win10toast` или `plyer`) либо всплывающее окно поверх всех окон.

## Архитектура

Код разделён по слоям: отдельный файл для БД, отдельный для GUI и логики уведомлений.

| Файл | Назначение |
|---|---|
| `models.py` | Модель `Reminder` (dataclass) с полями повтора и методом `get_next_trigger_time()`, константы статусов и интервалов, форматы и функции разбора даты/времени. |
| `db.py` | Слой доступа к SQLite3: подключение, автосоздание и миграция таблиц и индексов, CRUD, выборка сработавших напоминаний, пометка просроченных, перепланирование повторов. |
| `reminders.py` | Бизнес-логика `ReminderService`: добавление с валидацией, удаление, смена статуса, авто-просрочка, выдача сработавших напоминаний. |
| `notifier.py` | Показ уведомлений: автовыбор бэкенда `win10toast` → `plyer` → всплывающее окно tkinter поверх всех окон. |
| `gui.py` | Графический интерфейс на tkinter: таблица напоминаний, фильтр по статусу, диалог добавления, кнопки действий. |
| `main.py` | Точка входа: разбор аргументов командной строки и запуск приложения. |
| `requirements.txt` | Список зависимостей (обязательных нет; `win10toast`/`plyer` — опционально). |

### Схема базы данных

Таблицы создаются автоматически при первом запуске:

```sql
CREATE TABLE IF NOT EXISTS reminders (
    id              INTEGER PRIMARY KEY AUTOINCREMENT,
    title           TEXT    NOT NULL,
    description     TEXT    NOT NULL DEFAULT '',
    due_at          TEXT    NOT NULL,
    status          TEXT    NOT NULL DEFAULT 'Ожидает',
    notified        INTEGER NOT NULL DEFAULT 0,
    created_at      TEXT    NOT NULL,
    repeat_interval TEXT,
    repeat_end      TEXT
);
```

Дополнительно создаются индексы `idx_reminders_due` и `idx_reminders_status`.
При запуске существующая база автоматически дополняется новыми колонками
(`repeat_interval`, `repeat_end`), если их ещё нет.

## Статусы напоминаний

| Статус | Значение |
|---|---|
| **Ожидает** | Напоминание активно и ещё не сработало. Статус по умолчанию при создании. |
| **Готово** | Напоминание выполнено пользователем. |
| **Просрочено** | Время срабатывания прошло, но напоминание не было отмечено как «Готово» или «Отменено» (проставляется автоматически). |
| **Отменено** | Напоминание отменено пользователем. |

Активными (способными сработать) считаются статусы **«Ожидает»** и **«Просрочено»**.
Именно по ним приложение отслеживает наступление времени.

## Повторяющиеся напоминания

Напоминание может повторяться: **ежедневно** (`daily`), **еженедельно** (`weekly`)
или **ежемесячно** (`monthly`). Без повтора интервал равен `None`.

- При создании повторяющегося напоминания в базе сохраняется **одна** запись
  с текущим временем срабатывания и выбранным интервалом в поле `repeat_interval`.
- Метод `Reminder.get_next_trigger_time()` вычисляет следующее время срабатывания
  на основе текущего: `+1 день`, `+7 дней` или `+1 месяц` (для месячного интервала
  день ограничивается длиной месяца, например 31 января → 28/29 февраля).
- Поле `repeat_end` (дата) задаёт, до какого числа включительно повторяется
  напоминание. Если оно пусто, повтор не ограничен по дате.
- Когда пользователь отмечает повторяющееся напоминание как **«Готово»**,
  вызывается `ReminderService.process_completed_recurring(reminder_id)`:
  1. Находит запись в базе.
  2. Вычисляет новое время срабатывания.
  3. Если новое время не выходит за `repeat_end` (или `repeat_end` пуст) —
     обновляет время в той же записи, сбрасывает флаг уведомления и возвращает
     статус **«Ожидает»**.
  4. Если время вышло за пределы `repeat_end` — устанавливает статус **«Готово»**.

## Логика уведомлений

- Проверка сработавших напоминаний выполняется периодически (каждые **5 секунд**)
  через `root.after`, поэтому уведомления продолжают работать при свёрнутом окне.
- Порядок обработки в одном цикле проверки:
  1. Показ уведомлений для напоминаний, у которых время наступило, а уведомление ещё
     не показывалось (`notified = 0`, статус «Ожидает» или «Просрочено»).
  2. Автоматический перевод просроченных напоминаний в статус **«Просрочено»**.
  3. Обновление таблицы в интерфейсе.
- Порядок выбран так, чтобы уведомление не терялось при смене статуса.
- Каждое напоминание уведомляет **один раз** — после показа поле `notified`
  устанавливается в `1`.
- Напоминания, время которых прошло, пока компьютер был выключен, срабатывают
  один раз при следующем запуске приложения.
- Бэкенд уведомлений выбирается автоматически:
  - **win10toast** — системные тосты Windows 10 (если установлен);
  - **plyer** — системные уведомления Windows 10 (если установлен);
  - **всплывающее окно tkinter** — если ничего из перечисленного не установлено.

  Системные тосты показываются в отдельном потоке, всплывающее окно — через
  `root.after(0, ...)`, что потокобезопасно для tkinter.

## Установка и запуск

### 1. Виртуальное окружение (venv)

```powershell
python -m venv .venv
.venv\Scripts\Activate.ps1
```

### 2. Установка зависимостей

Обязательных зависимостей нет — приложение работает на стандартной библиотеке
Python (`tkinter` + `sqlite3`). Для выбора даты окончания повтора рекомендуется
установить `tkcalendar` (виджет `DateEntry`); без него используется обычное поле
ввода даты. Для системных уведомлений Windows 10 можно установить дополнительные
пакеты:

```powershell
pip install -r requirements.txt
```

### 3. Запуск

```powershell
python main.py
```

Запуск с собственным файлом базы данных:

```powershell
python main.py --db "C:\path\to\reminders.db"
```

По умолчанию база `reminders.db` создаётся рядом с исходным кодом.

> **Примечание.** `tkinter` входит в стандартную поставку Python для Windows.
> Если системные тосты (`win10toast`/`plyer`) не установлены, приложение
> автоматически использует всплывающее окно поверх всех окон.

## Управление в интерфейсе

- **Добавить** — открывает диалог создания напоминания
  (заголовок, описание, дата `ДД.ММ.ГГГГ`, время `ЧЧ:ММ`, кнопки быстрого сдвига
  «+5 минут», «+1 час», «+1 день»).
- **Повтор** — выпадающий список: «Нет», «Ежедневно», «Еженедельно», «Ежемесячно».
- **Дата окончания** — поле `DateEntry`, активно только при выбранном повторе;
  пустое значение означает повтор без ограничения по дате.
- **Готово / Отменить / Вернуть в ожидание** — меняют статус выбранных напоминаний.
  Для повторяющихся напоминаний «Готово» переносит их на следующее время.
- **Удалить** — удаляет выбранные напоминания после подтверждения.
- **Двойной клик** по строке отмечает напоминание как «Готово».
- **Фильтр по статусу** — выпадающий список «Все» + четыре статуса.
- В статусной строке отображаются счётчики по каждому статусу и текущий
  бэкенд уведомлений.
- Цветовая подсветка строк: просроченные — красные, готовые — зелёные,
  отменённые — серые.
